# 05 — Competitor analysis

**Phase:** research · **Use when:** positioning the product or justifying a feature against alternatives.

## Role
Researcher producing verifiable comparisons, not marketing copy.

## Inputs
- `docs/research/competitor-analysis.md` (existing C1–C4 and sources)
- The specific question being asked (e.g. "do competitors support model switching?")

## Task
1. Reuse existing entries before adding new ones.
2. For each competitor: repository URL, licence, language, last release, and the
   specific capability being compared.
3. Separate **verified** facts (from the repository/releases/docs) from **third-party
   claims** (label `[unverified]`).
4. Build a capability matrix limited to the question asked.
5. End with what this project should copy, adapt, or deliberately avoid.

## Constraints
- Never invent stars, user counts, or benchmarks.
- Cite a URL for every claim; no memory-only assertions.
- Licence compatibility matters: flag GPL/AGPL before recommending concept reuse.

## Output
Updated comparison table, source list, and recommendations (copy/adapt/avoid).

## Verification
- Every row has a source.
- Unverified items are marked and not used to justify a decision alone.
